### Assessment of the proposal

| Proposal | Decision | Reason |
| --- | --- | --- |
| Rust application host | Accept | It removes the large bundled JavaScript runtime and the reverse call into Go. |
| One installed binary | Accept | The host can embed browser files and run its own private tunnel supervisor mode. |
| Shared golden vectors | Accept, expand | Cover transactions, preimages, JSON rejection, lifecycle traces, and artifact mutations. |
| Shared Rust signing core | Accept as modules | A separate published core crate adds no required behavior. |
| Rust CLI before HTTP | Accept | Prove the byte contract before changing sessions and concurrency. |
| Port existing bridge | Change | Port the final accepted protocol v3 implementation, including its new tests and process-group cleanup. |
| Browser WASM core | Reject for this migration | It adds packaging, initialization, and shared failure modes without removing browser JavaScript. |
| Keep the TS pre-check | Accept | It also verifies returned artifacts independently. It is more than a display check. |
| Upstream Stellar CLI signer | Defer | It requires separate upstream interface work and does not replace the bridge. |
| Use prototype size as a target | Reject | The prototype omits the full service, TLS, cancellation, notices, and asset implementation. |
| Translate every test into Rust | Reject | Real JS SDK and browser interoperability tests need their original JavaScript environment. |

The Go split is not a security boundary. The raw signer already accepts any valid 32-byte digest.
However, removing the split changes cancellation, process identity, output handling, and 1Password approval caching.
The port must prove those behaviors. A smaller binary alone does not justify acceptance.

### Alternatives

| Design | Advantage | Cost | Decision |
| --- | --- | --- | --- |
| TS/Bun application | Lowest port effort; shared SDK implementation | Keeps the bundled runtime and JIT release requirements | Reject for the requested native end state |
| Go host and TS browser | Existing signer stays intact; simple standard HTTP library | Requires an XDR and lifecycle port anyway; adds Go XDR dependencies | Credible lower-risk alternative, but does not meet the selected Rust end state |
| Rust host and TS browser | Native artifact; direct maintained XDR types; one host language | More dependencies and new async/process failure modes | Select, with explicit parity and review gates |

### Transaction rules

Port the accepted v3 structural rules. Do not restore the v2 operation allowlist or fee caps.
Preserve operations, embedded authorizations, other preconditions, signatures, and all transaction body bytes.
Append exactly one signature to the correct envelope.
For a normal V1 envelope, match the selected key against transaction or operation sources.
For a fee-bump envelope, match the outer fee source and sign the outer fee-bump hash.
An inner source alone does not authorize this outer signing path.
Resolve muxed sources to their base Ed25519 key for matching only.
Keep at most 19 existing signatures and reject an already valid signature from the selected key.
Use the inner transaction's time bounds for fee bumps.
